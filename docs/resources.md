# Ресурсы

## Официальные ресурсы задания

### NASA

- **[Quickmap](https://quickmap.lroc.asu.edu/)** (ASU / LRO) — интерактивная карта Луны: снимки высокого разрешения, рельеф и другие слои с Lunar Reconnaissance Orbiter. Пригодится, чтобы смотреть места посадки и рельеф южного полюса.
- **[Moon Trek](https://trek.nasa.gov/moon/)** — 3D-визуализация Луны от NASA: рельеф и местность у мест посадки, помогает понять, как рельеф влияет на горизонт.
- **[Horizons System](https://ssd.jpl.nasa.gov/horizons/)** (JPL) — расчёт эфемерид: положения Солнца и Земли из любой точки на Луне. Основа для расчётов энергии и связи.

### Партнёрские агентства

- **CSA — [Moon Exploration](https://www.asc-csa.gc.ca/eng/astronomy/moon-exploration/)** — портал Канадского космического агентства о лунных миссиях и участии в Artemis. Полезен для контекста и списка миссий.

> NASA не отвечает за содержимое сайтов, не принадлежащих правительству США; при использовании их данных нужно соблюдать их условия.

## Наши заметки

### Horizons API — Солнце и Земля с поверхности Луны

У Horizons есть REST API: `https://ssd.jpl.nasa.gov/api/horizons.api`. Наблюдатель задаётся точкой на поверхности Луны, в ответе — азимут и высота над горизонтом.

| Параметр       | Значение                           | Смысл                                      |
|----------------|------------------------------------|--------------------------------------------|
| `COMMAND`      | `'10'` — Солнце, `'399'` — Земля   | Цель                                       |
| `CENTER`       | `'coord@301'`                      | Наблюдатель на поверхности Луны (301)      |
| `COORD_TYPE`   | `'GEODETIC'`                       | Координаты как долгота/широта/высота       |
| `SITE_COORD`   | `'lon,lat,alt_km'`                 | Восточная долгота, широта (°), высота (км) |
| `EPHEM_TYPE`   | `'OBSERVER'`                       |                                            |
| `START_TIME` / `STOP_TIME` / `STEP_SIZE` | `'2026-12-01'`, `'2026-12-02'`, `'1 h'` | Интервал и шаг            |
| `QUANTITIES`   | `'4'`                              | Видимые азимут и высота (°)                |

Пример (Земля из точки у южного полюса):

```bash
curl -s -G "https://ssd.jpl.nasa.gov/api/horizons.api" \
  --data-urlencode "format=text" --data-urlencode "COMMAND='399'" \
  --data-urlencode "CENTER='coord@301'" --data-urlencode "COORD_TYPE='GEODETIC'" \
  --data-urlencode "SITE_COORD='31.2,-89.45,0'" --data-urlencode "MAKE_EPHEM='YES'" \
  --data-urlencode "EPHEM_TYPE='OBSERVER'" --data-urlencode "START_TIME='2026-12-01'" \
  --data-urlencode "STOP_TIME='2026-12-02'" --data-urlencode "STEP_SIZE='6 h'" \
  --data-urlencode "QUANTITIES='4'"
```

Данные — между `$$SOE` и `$$EOE`: дата, азимут, высота. Проверено, работает.

Важно:

- Высота считается относительно **гладкой сферы** (R = 1737.4 км), без рельефа. Либрация Земли и орбита Луны уже учтены.
- Высоту точки (`alt_km`) лучше брать из рельефа LOLA: на полюсе перепады в несколько километров.
- Чтобы не упираться в лимиты API, эфемериды для мест и дат можно посчитать заранее и кешировать на бэкенде. Альтернатива — считать локально через SPICE-ядра JPL (`spiceypy`) или `skyfield`.

### Рельеф и горизонт

Задание прямо советует учитывать рельеф: на полюсе Солнце и Земля висят у самого горизонта, и гребень кратера может закрыть их полностью.

Идея расчёта:

1. Берём цифровую модель рельефа (DEM) LOLA. Используем полярную сетку из архива PDS Geosciences Node: [`ldem_75s_120m`](https://pds-geosciences.wustl.edu/lro/lro-l-lola-3-rdr-v1/lrolol_1xxx/data/lola_gdr/polar/img/) — 75–90° ю.ш., 120 м/пиксель, полярная стереографическая проекция, int16 × 0.5 м над сферой 1737.4 км. Там же есть 60/30/20/10 м, но это сотни мегабайт и гигабайты. Для детальных локальных моделей есть NASA PGDA (`pgda.gsfc.nasa.gov`).
2. Для каждого азимута (шаг ~1°) ищем максимальный угол возвышения рельефа — получаем **маску горизонта**.
3. Солнце/Земля видимы, если их высота из Horizons больше маски на этом азимуте. Солнце — диск ~0.53°, поэтому бывает частичное освещение.

Маску горизонта для точки считаем один раз, а потом быстро проверяем любые даты.
