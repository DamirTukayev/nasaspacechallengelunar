# План MVP

## Что показываем на демо

Пользователь выбирает место посадки (из списка или по координатам) и интервал дат и сразу видит:

1. **Небо над местом** — панорама 360°: силуэт горизонта по рельефу, траектории Солнца и Земли.
2. **Таймлайн** — высота Солнца и Земли во времени, закрашены окна освещённости и связи. Ползунок времени синхронизирован с панорамой, есть проигрывание.
3. **Метрики** — высота Солнца сейчас, сколько до заката и до захода Земли, % времени на солнце, % времени со связью, самая длинная ночь, итоговая оценка (зелёный / жёлтый / красный).
4. **Сравнение** — 2–4 сценария (место + даты) рядом, видно, какой лучше и почему.
5. **Вау-режим «Mission Control»** — первый экран сайта: полноэкранный пролёт к полюсу, посадка и вычисления, которые происходят на глазах. Подробно — в разделе «Вау-режим» ниже.

Главная мысль демо: *сдвиг на пару километров или на пару недель меняет всё* — и это видно за секунды, а не за час в Horizons.

## Объём

**Входит в MVP:**

- каталог мест: Apollo, места у южного полюса (кандидаты Artemis III, цели CLPS), миссии других стран, свои координаты;
- эфемериды Солнца и Земли через JPL Horizons с кешем;
- маска горизонта по рельефу LOLA для южного полюса (для остальных мест — гладкая сфера);
- панорама неба, таймлайн, метрики, сравнение сценариев.

**Не входит (если останется время):**

- ~~3D-поверхность (three.js)~~ — сделано: 3D-сцена места с рельефом, светом и анимацией посадки;
- карта мест на снимке полюса;
- «календарь» — тепловая карта освещённости по датам на месяцы вперёд;
- образовательный режим с подсказками «почему так».

## Контракт API (черновик)

Фронт и бэк договариваются о контракте в первый же день. До готовности бэка фронт работает на моках с такой же структурой. Актуальная схема — в OpenAPI, который генерирует FastAPI (`/docs`).

```
GET  /api/sites
     → [{ id, name, group, lat, lon, alt_m, landing_date, description, source }]
     group: "Apollo" | "CLPS" | "International" | "South Pole"
     lat/lon: градусы, планетоцентрические, Mean Earth/Polar Axis, долгота восточная (−180…180)
     alt_m: высота относительно сферы 1737.4 км или null (заполним из LOLA в B4)
     landing_date: "YYYY-MM-DD" (UTC) или null

GET  /api/sites/{id}
     → один объект, 404 если нет

GET  /api/ephemeris?lat=&lon=&alt_m=0&start=&end=&step_minutes=60
     → {
         times: ["2026-12-01T00:00:00Z", ...],
         sun:   { azimuth: [...], elevation: [...] },
         earth: { azimuth: [...], elevation: [...] },
         step_minutes
       }
     Колоночный формат: i-й элемент каждого массива относится к times[i].
     Азимут — от севера по часовой, высота — над горизонтом гладкой сферы (без рельефа), градусы.
     Время в UTC. Не больше 20 000 точек; 422 при неверном интервале, 502 если Horizons недоступен.
     Источник — JPL Horizons, ответы кешируются на диске (backend/data/cache/).

GET  /api/horizon?lat=&lon=&observer_height_m=2
     → {
         kind: "terrain" | "sphere",
         azimuths: [0, 0.5, ..., 359.5],            // от севера по часовой
         elevations: [...],                          // высота горизонта, градусы (может быть < 0 на вершинах)
         site_alt_m,                                 // высота точки по DEM, null для "sphere"
         observer_height_m,
         dem                                         // "ldem_75s_120m" или null
       }
     "terrain" — южнее 75° ю.ш., если скачан DEM; иначе ровный горизонт 0°.

GET  /api/terrain?lat=&lon=&half_extent_km=20&size=201
     → {
         kind: "terrain" | "sphere",
         size, half_extent_m,
         heights: [...],    // size × size, по строкам: строка 0 — север, столбец 0 — запад;
                            // метры над плоскостью грунта в точке, кривизна Луны учтена
         site_alt_m, dem
       }
     Для 3D-сцены места посадки. Вне DEM — гладкая сфера (только кривизна).

POST /api/analyze
     { lat, lon, alt_m?, start, end, step_minutes = 60,
       observer_height_m = 2, min_earth_elevation_deg = 0 }
     alt_m по умолчанию берётся из DEM (или 0, если DEM нет)
     → {
         horizon_kind: "sphere" | "terrain",
         site_alt_m,
         series: {                                   // колоночный формат, как в /api/ephemeris
           times,
           sun:   { azimuth, elevation, skyline, visible_fraction },
           earth: { azimuth, elevation, skyline, visible }
         },
         windows: {
           sun, earth, both: [{ start, end, duration_hours, starts_before_range, ends_after_range }]
         },
         metrics: {
           sunlit_pct, earth_visible_pct, both_pct,
           mean_sun_disk_fraction, max_sun_el, mean_sun_el_sunlit,
           next_sunrise, next_sunset, next_earthrise, next_earthset,
           longest_dark_hours, longest_no_earth_hours,
           verdict: "green" | "yellow" | "red", verdict_reasons: [string]
         }
       }
```

Правила расчёта в `/api/analyze`:

- `skyline` — высота горизонта (рельефа) на азимуте Солнца / Земли, из той же маски, что отдаёт `/api/horizon`. Для `horizon_kind: "sphere"` везде 0°.
- Маска горизонта: из точки на высоте `observer_height_m` над грунтом идём лучами с шагом 0.5° по азимуту до 200 км, по рельефу LOLA считаем угол возвышения каждой точки по точным 3D-координатам на сфере (кривизна Луны учтена, рефракции нет) и берём максимум.
- **Солнце** — диск радиусом 0.2666°. `visible_fraction` — доля диска над горизонтом (0…1). «Солнце есть», пока над горизонтом виден верхний край.
- **Земля** видна, когда её центр выше горизонта на `min_earth_elevation_deg`.
- Границы окон интерполируются между точками сетки. `starts_before_range` / `ends_after_range` — окно уже было открыто в начале интервала / ещё открыто в конце.
- `next_*` — первое событие внутри интервала или `null`.
- Вердикт: красный, если солнце < 40% времени, Земля < 20% или самая длинная ночь > 100 ч; жёлтый, если солнце < 75%, Земля < 50% или ночь > 24 ч; иначе зелёный. Причины — в `verdict_reasons`.

## Бэкенд (FastAPI)

Стек: Python 3.11+, FastAPI, pydantic, httpx, numpy, rasterio, pytest.

| #  | Задача | Что готово в конце |
|----|--------|--------------------|
| B1 | **Каркас** — структура `backend/`, FastAPI, CORS, `/health`, зависимости, инструкция запуска в README | `uvicorn` запускается, фронт может достучаться |
| B2 | **Каталог мест** — JSON с местами посадки и `GET /api/sites`. Координаты брать из источников (Quickmap, публикации NASA), указать источник у каждого места | Список из 15–25 мест |
| B3 | **Эфемериды** — клиент Horizons: Солнце (`10`) и Земля (`399`) из `coord@301`, разбор ответа, кеш на диске по (место, интервал, шаг) | Функция → ряды az/el; повторный запрос не идёт в сеть |
| B4 | **Рельеф и маска горизонта** — скачать DEM LOLA южного полюса, для точки посчитать максимальный угол возвышения рельефа по каждому азимуту с учётом кривизны Луны, `GET /api/horizon` | Маска для любой точки у полюса, кеш |
| B5 | **Анализ** — `POST /api/analyze`: совмещаем эфемериды и маску, доля видимого солнечного диска, окна видимости, метрики, вердикт | Полный ответ по контракту |
| B6 | **Тесты** — разбор Horizons, маска на синтетическом рельефе, поиск окон | `pytest` зелёный |

Порядок: B1 → B2 и B3 параллельно → B5 на гладкой сфере → B4 → B5 с рельефом → B6 по ходу.

Формула для маски (точка наблюдения O, точка рельефа T на расстоянии d по поверхности):

```
угол = atan( (h_T − h_O − d² / (2R)) / d ),   R = 1737.4 км
```

Маска на азимуте — максимум угла по всем точкам вдоль луча (до ~100–150 км).

## Вау-режим «Mission Control»

### Зачем

Всё нужное приложение уже считает, но показывает это как инструмент: форма, карточки, графики. Жюри и зритель должны в первые секунды **почувствовать**, что происходит. Человек открывает сайт — и сразу на весь экран:

- пролёт к южному полюсу и посадка;
- на глазах считаются горизонт, свет и связь;
- за минуту проходят лунные сутки.

Инструмент для планировщиков остаётся рядом, одной кнопкой.

Главное правило: **вся анимация — это настоящие вычисления**, а не декорация.
- Каждый луч, траектория или процент на экране берутся из тех же данных, что и вердикт.
- Счётчики показывают реальные объёмы: 720 азимутов, ~647 000 точек рельефа LOLA на один горизонт, 709 положений Солнца и Земли из JPL Horizons на лунные сутки с шагом в час.

### Первая минута на сайте (раскадровка)

| Время | Что на экране | Какие вычисления видны |
|---|---|---|
| 0–3 с | Звёзды, название; в кадр выплывает Луна, южный полюс к зрителю | Метки мест из каталога загораются на глобусе |
| 3–8 с | Камера ныряет к полюсу | Подписи: широта, высота над поверхностью |
| 8–14 с | Глобус плавно сменяется рельефом LOLA ±20 км; посадка модуля с работающим двигателем | HUD спуска: высота, вертикальная скорость, тяга |
| 14–20 с | Касание, пыль. Из модуля веером расходятся 720 лучей, каждый останавливается на самой высокой точке рельефа, по ним рисуется кольцо горизонта | Счётчики: азимуты, точки рельефа, 200 км; итоговый горизонт |
| 20–28 с | Над местом встаёт небесная полусфера, по ней прорисовываются дуги Солнца и Земли | «JPL Horizons: 709 положений», отметки точек появляются по мере загрузки |
| 28–60 с | Лунные сутки за полминуты: тени ползут по рельефу, на рельефе накапливается тепловая карта освещённости, луч связи к Земле включается и гаснет, внизу растут полосы окон | Живые счётчики: % солнца, % связи, «солнце + связь», самая длинная ночь; в конце вердикт для выбранного типа миссии |
| дальше | HUD-кнопки: «Соседние точки» (карта лучших мест), «Сравнить», «Открыть планировщик» | — |

Индикатор доли видимого солнечного диска | фронт | При проигрывании видно, в какой момент и чем закрывается Солнце или связь |

**Порядок:** W1 → W4 → W3 → W7 → W2 → W5 → W6 → W8 → W9.
- **Если времени мало**, минимальный вау: W1 + W3 + W4 + W7 (≈ 2,5 человеко-дня). Это уже «зашёл — и на весь экран посадка и расчёты».
- **Полный вариант** ≈ 6–7 человеко-дней.
- **Параллелится:** бэкенд W3 (точки упора лучей) и фронт W1/W4 можно делать одновременно.

### Риски вау-режима

- **Накопление освещённости на GPU (W6) сложнее, чем кажется** → сначала запасной вариант с бэкенда по сетке, GPU — улучшение.
- **Тяжёлые текстуры Луны** → сжатые KTX2/WebP, ленивая загрузка, во время загрузки показываем звёзды и название.
- **Слабые телефоны** → упрощённый режим без теней и тепловой карты, честная подпись.
- **Пролёт мешает тем, кто пришёл работать** → кнопка «Пропустить», после первого просмотра пролёт не повторяется (запоминаем в `localStorage`), прямая ссылка на планировщик.

## Этапы

1. **Старт** — C1, B1, F1. Фронт на моках, бэк отвечает `/health` и `/api/sites`.
2. **Сквозной сценарий** — B3, B5 без рельефа; F2–F5 на реальном API. Уже можно показывать.
3. **Рельеф** — B4, пересчёт B5 с маской; панорама рисует настоящий горизонт.
4. **Сравнение и полировка** — F6, F7, B6, деплой.
5. **Вау-режим «Mission Control»** — W1–W9 (минимум W1, W3, W4, W7). Становится первым экраном сайта и основой демо и видео.
6. **Сдача** — C3–C5, заморозка `main` за несколько часов до дедлайна.

## Риски

- **Horizons медленный или ограничивает запросы** → кешировать, заранее прогреть кеш для мест из каталога; запасной вариант — считать локально через `skyfield` / SPICE.
- **DEM большой и тяжёлый** → взять разрешение пониже (20–100 м/пиксель), вырезать окно вокруг точки, маски для мест из каталога посчитать заранее.
- **Не успеваем рельеф** → MVP на гладкой сфере уже рабочий; рельеф — улучшение, а не блокер.
