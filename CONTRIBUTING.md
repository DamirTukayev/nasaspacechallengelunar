# Как мы работаем

## Роли

- **Дамир** — ревьювер и мейнтейнер. Коммитит напрямую в `main`, принимает и мержит PR.
- **Остальные участники** — работают в своих ветках и заливают изменения в `main` только через Pull Request.

## Стек

| Часть    | Технологии                   | Папка       |
|----------|------------------------------|-------------|
| Frontend | React + TypeScript (Vite)    | `frontend/` |
| Backend  | Python, FastAPI              | `backend/`  |

Стек и структура пока черновые — будем уточнять по ходу.

## Порядок работы

1. Обнови `main` перед началом задачи:
   ```bash
   git checkout main
   git pull
   ```
2. Создай ветку от `main`:
   ```bash
   git checkout -b feat/short-description
   ```
   Префиксы веток:
   - `feat/` — новая функциональность
   - `fix/` — исправление бага
   - `refactor/` — переработка без изменения поведения
   - `docs/` — документация
   - `chore/` — настройка, зависимости, CI
3. Коммить небольшими осмысленными шагами (формат — ниже).
4. Запушь ветку и открой PR в `main`:
   ```bash
   git push -u origin feat/short-description
   ```
5. Дождись ревью. Замечания исправляй новыми коммитами в ту же ветку.
6. После одобрения Дамир мержит PR (squash merge). Ветку после мержа удаляем.

## Правила

- **Не пушить напрямую в `main`.** Только через PR.
- Один PR — одна задача. Маленький PR ревьюится быстрее.
- Перед PR подтяни свежий `main` и разреши конфликты у себя:
  ```bash
  git fetch origin
  git rebase origin/main
  ```
- Перед PR проверь, что проект запускается и ничего не сломалось.
- Не коммить секреты (`.env`, ключи API), большие бинарники и сгенерированные файлы (`node_modules/`, `dist/`, `__pycache__/`, `.venv/`).
- Если правишь и фронт, и бэк (например, меняешь API) — опиши в PR, что поменялось в контракте.

## Коммиты

Формат [Conventional Commits](https://www.conventionalcommits.org/), на английском, в повелительном наклонении:

```
feat: add lunar map component
fix: handle empty response from /api/sites
docs: describe backend setup
```

Можно указывать область: `feat(frontend): ...`, `fix(backend): ...`.

## Pull Request

- Заголовок — в том же формате, что и коммит.
- В описании: что сделано, зачем, как проверить. Для UI — скриншот.
- Связанная задача, если есть: `Closes #12`.
